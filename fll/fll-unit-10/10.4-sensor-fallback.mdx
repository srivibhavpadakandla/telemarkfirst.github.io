# Lesson F10.4: Handle Missing or Conflicting Cues

A missing sensor reading needs a defined outcome in a mission program. Here the robot waits briefly for a valid ultrasonic distance. It moves only when the reading is valid and leaves enough room; otherwise it stops. This makes the decision visible in the printed result.

## Worked example

The `valid` flag begins false and changes only after a reading below 2000. The one-second limit prevents the polling loop from waiting indefinitely.

~~~python
watch = StopWatch()
valid = False
while watch.time() < 1000:
    range_mm = distance_sensor.distance()
    if range_mm < 2000:
        valid = True
        break
    wait(20)
if valid and range_mm > 150:
    robot.straight(100)
else:
    robot.stop()
print("Valid range:", valid)
~~~

## Simulator practice

Start with the worked example's `valid` check. Temporary sample values of 100 and 2000 mm can exercise both branches before the fixed-field reading is used; the printed flag can show which branch ran.

## On the robot

The physical test should begin at low speed in clear space. If invalid readings are common, the team can decide whether this mission should be skipped or approached another way.

## Check and adjust

An invalid reading should leave the drive base stopped and print `False`. If it moves, inspect where the `valid` flag changes and which branch uses it.
