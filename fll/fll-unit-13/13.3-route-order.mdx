# Lesson F13.3: Order Missions

Changing mission order can change travel time, attachment handling, and the return path after a failure. This lesson compares two orders using measured time and a clear launch plan. The order should also leave a safe return if an uncertain action does not work.

## Worked example

The list prints a proposed sequence and launch number. It does not execute the missions, so the simulator practice needs routes for the selected order.

~~~python
mission_order = ["line", "target", "delivery"]
for launch_number, mission in enumerate(mission_order, start=1):
    print("Launch", launch_number, mission)
~~~

## Simulator practice

The worked list only prints an order. Turn it into route calls before comparing two sequences on the practice field; total time and ending position can show differences that the list alone cannot.

## On the robot

Attachments can be laid out in launch order for a physical rehearsal. The people who will run the match can time the handoff between programs.

## Check and adjust

The written plan should connect each launch to a program, attachment, mark, expected time, and return route. A second launch needs a known starting pose before its timing is meaningful.
