# Lesson F14.3: Test the Whole Route

After individual actions work, we can run them in match order. An integration test keeps the planned launch marks, attachment, and program selection together and records a result after each action. Those intermediate results can show where a full route first changes from the plan.

## Worked example

The printed distance and tool angle are checkpoints after the approach and tool move. The final time describes the full sequence, but the field view is still needed to confirm home position and clearance.

~~~python
watch = StopWatch()
robot.straight(300)
print("Approach mm:", robot.distance())
attachment.run_angle(160, 60)
print("Tool deg:", attachment.angle())
robot.straight(-300)
print("Total ms:", watch.time())
~~~

## Simulator practice

Run the worked route three times from the same start. A table for approach, tool action, return, and elapsed time can reveal which result varies.

## On the robot

The match team should run the physical sequence with the intended attachment. Record the first incorrect action in each unsuccessful trial, including handling errors.

## Check and adjust

The log should make the first incorrect result visible without relying only on final score. That action can then be retested from a known pose.
