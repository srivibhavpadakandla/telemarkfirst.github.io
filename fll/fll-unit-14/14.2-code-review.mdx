# Lesson F14.2: Review Units and Stops

Before the whole route runs, a code review can catch unit mistakes and missing stop conditions. DriveBase distance uses millimeters, angles use degrees, motor speeds use degrees per second, and waits use milliseconds. This lesson tests both a quick timeout and a normal approach to see whether the drive stops in each case.

## Worked example

The loop ends when the object is close enough or the time limit is reached. A 2000 mm invalid reading is not treated separately in this sample, so a robust mission would check for it before interpreting the returned Boolean.

~~~python
def approach_safely(limit_ms):
    watch = StopWatch()
    robot.drive(100, 0)
    while distance_sensor.distance() > 150 and watch.time() < limit_ms:
        wait(10)
    robot.stop()
    return watch.time() < limit_ms

print("Cue found:", approach_safely(3000))
~~~

## Simulator practice

Put the worked `approach_safely()` function in the editor, then compare a 1 ms timeout with the normal 3000 ms limit. Both should reach `robot.stop()`, although their returned results may differ.

## On the robot

One teammate can read movement calls and units while another checks them against the field and port map. A missing sensor cue should also be tried at low speed.

## Check and adjust

The review log should name each continuous drive's stop path and the failure cases tested. If a cue is absent, the timer, stop call, and returned result should agree.
