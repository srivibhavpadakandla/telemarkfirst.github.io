# Lesson F14.1: Organize the Program

A final program should make its measured values and mission routes easy for teammates to find. We can group imports and device setup, constants, functions, and launch calls in that order. This lesson reorganizes a practice program so a calibration change has one clear place to go.

## Worked example

The threshold is named once and used by the mission function. The returned Boolean tells the caller what the sensor saw at the end of the straight drive; it does not by itself stop at a line.

~~~python
WHEEL_DIAMETER_MM = 56
AXLE_TRACK_MM = 112
LINE_THRESHOLD = 35

def line_mission():
    robot.straight(250)
    return color_sensor.reflection() < LINE_THRESHOLD

result = line_mission()
print("Line mission:", result)
~~~

## Simulator practice

Use the worked function or another practice route to arrange setup, constants, functions, and calls in four groups. Running before and after can check that organization changed without changing route behavior.

## On the robot

A teammate can read a printed program and locate the ports, wheel geometry, and main launch function. Any hard-to-find value is a candidate for a named constant.

## Check and adjust

The revised file should show which values come from measurements and where they are used. A teammate's ability to find and explain one value is a useful check.
