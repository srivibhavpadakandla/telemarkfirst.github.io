# Lesson F7.2: Relative Tool Angles

Now that a positive direction is known, we can use relative angles to move the tool out and back. `Motor.run_angle()` adds each requested rotation to the current motor position. A positive move followed by an equal negative move should bring the motor near its starting angle if the mechanism can complete both moves.

## Worked example

`start_deg` records the initial motor angle. The two `run_angle()` calls request 90 degrees out and 90 degrees back. The printed values can show whether the motor returned to its recorded start.

~~~python
start_deg = attachment.angle()
attachment.run_angle(180, 90)
print("After push:", attachment.angle())
attachment.run_angle(180, -90)
print("Back at:", attachment.angle(), "start:", start_deg)
~~~

## Simulator practice

The simulator starter moves the attachment and prints its angle. Using the example's out-and-back pair should end near `start_deg`. Changing the first move to 60 degrees while leaving the return at 90 should produce a different final angle.

## On the robot

Three physical out-and-back moves from a marked start may show whether the tool returns to the same place. A blocked mechanism can stop before the requested angle, so clearance matters as much as the printed motor value.

## Check and adjust

The motor reading should be close to its start after equal and opposite moves. If the physical tool is not, compare both printed angles and inspect the linkage for binding or slip.
