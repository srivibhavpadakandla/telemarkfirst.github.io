# Lesson F2.5: First Mission Run Capstone

The first mission run brings the earlier pieces together. The simulator checks whether the robot activates the target, delivers the object, and returns home within 150 seconds without a collision. Functions can keep the target action and return route separate while you test each part.

## Worked example

The [course port map](/fll/python-starter) supplies the device names below. `target_action()` and `return_home()` show how two route parts can be named. This fragment does not reach every field objective by itself; a complete route needs a pickup and delivery action at the corresponding field positions.

~~~python
def target_action():
    robot.straight(250)
    attachment.run_angle(180, 90)
    attachment.run_angle(180, -90)

def return_home():
    robot.turn(180)
    robot.straight(250)

target_action()
return_home()
~~~

## Simulator practice

The field view can help you place the target action, pickup, and release along one route. The three simulator checks should show target activation, delivery, and a return home within 150 seconds. Keeping the launch pose fixed between attempts makes route changes easier to compare.

## On the robot

On a practice field, three runs from the same launch marks may show whether the target and delivery actions repeat. Record the first missed position in each run before deciding what to change.

## Check and adjust

The simulator checks should pass before a physical run is treated as a match plan. The notes from three mat trials can show whether a miss begins at the target, the cargo pickup, the release, or the return. A function for the first missed action can be tested on its own.
