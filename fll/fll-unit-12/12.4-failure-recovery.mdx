# Lesson F12.4: Recover from a Failed Cue

A mission may need a different route when a sensor cue is missed. Here the approach function returns `True` only if the dark line is detected before the timeout. The tool action depends on that result; otherwise the robot takes a short return path.

## Worked example

The function stops the drive before returning its Boolean. The reverse distance in the `else` branch is an example and should be checked against the actual path home.

~~~python
def approach_with_timeout():
    watch = StopWatch()
    robot.drive(90, 0)
    while color_sensor.reflection() > 35 and watch.time() < 2500:
        wait(10)
    robot.stop()
    return color_sensor.reflection() <= 35

if approach_with_timeout():
    attachment.run_angle(160, 60)
else:
    print("Skip tool action")
    robot.straight(-150)
~~~

## Simulator practice

Use the worked example's approach and return branches. Setting its threshold below zero should force the failed-cue branch; compare that run with the measured threshold and check whether the attachment moves only after a detected line.

## On the robot

The physical failed-cue test should begin from a safe launch. Its reverse path needs enough clearance for the actual tool, even when the line is missed.

## Check and adjust

A missed line should leave the tool still and lead to the planned return. If the tool moves, the returned value and its `if` condition are the first places to inspect.
