# Lesson F12.1: Record Repeatability

A single successful run does not show how often a route works. Repeating the same program from the same launch marks can reveal variation in final position, heading, time, and mission result. This lesson introduces a mean and a spread for time, then uses a table to keep all outcomes visible.

## Worked example

The mean describes the center of these three times. The spread is the longest minus the shortest, so a large spread may point to inconsistent starts or motion.

~~~python
times_ms = [3200, 3350, 3280]
mean_ms = sum(times_ms) / len(times_ms)
spread_ms = max(times_ms) - min(times_ms)
print("Mean ms:", mean_ms)
print("Spread ms:", spread_ms)
~~~

## Simulator practice

The starter provides a fixed drive for the automatic three-profile table. Those profiles represent different calibrations, so their results should be recorded separately from repeated physical trials.

## On the robot

Five physical trials from the same launch marks can show how much the actual result varies. Include failed runs and their endpoints in the table.

## Check and adjust

The table should make the spread and any consistent error visible. If results vary widely, launch alignment and loose hardware are useful checks before changing a calibration number.
