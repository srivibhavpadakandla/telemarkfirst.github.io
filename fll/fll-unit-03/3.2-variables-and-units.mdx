# Lesson F3.2: Variables and Units

Once a value has a name, its unit should be clear too. DriveBase distances use millimeters, while a field measurement may be written in centimeters. In this lesson we will convert a 30 cm target to 300 mm once, then use the converted value for the drive. A name such as `target_mm` can help keep the two units apart.

## Worked example

`TARGET_CM * 10` converts centimeters to millimeters. The print line exposes the converted value before `robot.straight(target_mm)` uses it. The speed and turn settings use their own units, shown in the code comment.

~~~python
TARGET_CM = 30
target_mm = TARGET_CM * 10
speed_mm_s = 150
print("Target:", target_mm, "mm")
robot.settings(speed_mm_s, 300, 90, 180)  # mm/s, mm/s², deg/s, deg/s²
robot.straight(target_mm)
~~~

## Simulator practice

A second run with `TARGET_CM = 40` should send 400 mm to `robot.straight()`. The printed target and final pose can help you check that the conversion happened once.

## On the robot

A centimeter measurement from the practice mat should be converted before it is used by the DriveBase. Writing both values in a notebook can make a tenfold unit error easier to notice when you compare the route with tape marks.

## Check and adjust

The code's `target_mm` and the notebook's converted value should agree. If a 30 cm plan commands only 30 mm, the missing factor of ten is a useful first check.
