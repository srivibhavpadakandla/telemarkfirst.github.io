# Lesson F3.4: Print Useful Diagnostics

We have printed values to inspect a route. A reading is more useful when its label says where it was taken and what unit it uses. Here we will print the launch range, a heading after a drive, and reflected light so a later run can be compared line by line.

## Worked example

Each `print()` call puts a route point or measurement name beside the value. `distance_sensor.distance()` reports millimeters and `hub.imu.heading()` reports degrees. The text labels do not change the robot's motion; they help explain the output after the drive.

~~~python
print("launch range mm:", distance_sensor.distance())
robot.straight(200)
print("after 200 mm, heading deg:", hub.imu.heading())
print("reflection percent:", color_sensor.reflection())
~~~

## Simulator practice

The example should produce three labeled lines. After a different straight distance, comparing those lines from the same start may show which readings changed with the robot's position.

## On the robot

On the physical robot, the same labels can make a test log easier to match with the route. Moving the robot by hand before a drive may show which sensor values respond to position or heading changes.

## Check and adjust

A useful log entry should include enough context to identify the reading later. If two values look alike but were taken at different places, the route-point labels may explain the difference.
