# Lesson F6.3: Scope and Calibration Constants

We can give a measured threshold one name and use it in more than one function. A variable created inside a function is local to that function, while a value defined above it can be read by both. Here `LINE_THRESHOLD` is the shared value and `light_percent` is the local reading.

## Worked example

`is_on_line()` reads reflection when called and compares it with `LINE_THRESHOLD`. The uppercase name signals a value the team intends to keep fixed during a run. A different measured threshold can be tried by changing that one definition.

~~~python
LINE_THRESHOLD = 35

def is_on_line():
    light_percent = color_sensor.reflection()
    return light_percent < LINE_THRESHOLD

print(is_on_line())
~~~

## Simulator practice

The simulator starter prints a reflection reading. Put that reading in `is_on_line()`, then rerun with a different `LINE_THRESHOLD`. The changed Boolean can show that the function uses the named value.

## On the robot

Physical light and dark readings may give a different threshold from the simulator's. Keeping those ranges beside the constant in the team's notes can show why that value was chosen.

## Check and adjust

Changing the shared constant should affect every call that reads it. If one call behaves differently, a second threshold literal or a local value may be hiding the intended constant.
