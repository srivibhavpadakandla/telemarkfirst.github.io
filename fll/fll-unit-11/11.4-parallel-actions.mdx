# Lesson F11.4: Coordinate Drive and Tool Motion

Once a drive and tool action work in sequence, some robots can perform them at the same time. That may shorten a route, but the tool needs clearance along the whole drive. Here the simulator shows the sequential actions; the hardware-only `wait=False` option introduces overlap after the route has been checked.

## Worked example

The first part is suitable for the simulator. The commented lines show how Pybricks can start a tool move without waiting and later check whether it is done. The simulator does not model that concurrent timing.

~~~python
# Simulator: test the same actions in sequence.
robot.straight(250)
attachment.run_angle(180, 60)
robot.straight(150)
print("Tool done:", attachment.done())

# Hardware-only timing option:
# attachment.run_angle(180, 60, wait=False)
# robot.straight(150)
# while not attachment.done():
#     wait(10)
~~~

## Simulator practice

Use the sequential route from the worked example and note its time and clearance. That baseline can be compared with a later physical test of overlapping motion.

## On the robot

The hardware-only option should first be checked with the robot raised. A later low-speed field trial can show whether it saves time without bringing the tool into an obstacle.

## Check and adjust

The overlapping route is useful only if the tool clears the models and its measured time improves. A collision or uncertain clearance is a reason to use the tested sequential version.
