# Lesson 5.1: Break a Program into Smaller Parts

**Decomposition** divides a program into parts with clear jobs. In a robot mission, route data, threshold checks, movement, and reporting can be tested separately before the full sequence runs. Start with the required result, list the inputs and outputs, then choose functions for steps that repeat or need a clear boundary.

## Plan a status check

In no more than six numbered steps, plan a program that stores three readings and reports whether each is at least 5. Keep the readings in a list and use a `reportReading` function with one parameter for each value. Test 4, 5, and 6 to cover both sides of the threshold and the boundary. Fixed test values let you check the decision before adding a real sensor.
